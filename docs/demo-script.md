# ClassPulse — two-minute demo script

Timings follow `docs/Build_Instructions.md` §9. Three browser profiles (or devices): **Instructor** on the big screen, **Student A** (the confused student) and **Student B** (the helper). Button labels below are the ones in the merged UI.

## Pre-demo checklist (10 minutes before)

1. **Re-push the backend.** The dev deployment is shared by several branches, so whatever was pushed last is live. From the checkout you are demoing: `npx convex dev --once` (then leave `npx convex dev` and `npm run dev` running). Check `npx convex env list` shows `ANTHROPIC_API_KEY` and `CLAUDE_MODEL`.
2. **Reset the demo data:** `npx convex run seed:reset`. Copy the printed `localStorage.setItem("classpulse:instructor:<sessionId>", "<secret>")` line and the `/instructor/<sessionId>` URL.
3. **Decide the Claude path now, before anyone joins.** Instructor profile: open the printed URL, paste the `localStorage.setItem(...)` line into the dev-tools console, reload, press **Suggest clusters (7 pending)** once. If it comes back `error` or takes > 20 s, plan to use the fallback in 00:35 below. Then reset again — `npx convex run seed:reset` — so the throwaway run is gone. The reset deletes every participant, helper opt-in and run of the old session, which is why steps 4–5 come *after* it.
4. **Instructor profile:** paste the *new* `localStorage.setItem(...)` line from step 3's reset, reload. Expect the four metric cards **Participants 24** (*incl. 24 simulated*), **Responses 106**, **Confused responses 42**, **Open clusters 1**; on the graph *Call stack & frames* and *Return values* red/amber, each with an amber **1 cluster** badge (the seeded cluster touches both), *Base case* green, N on every node; below the graph the cluster queue with **Suggest clusters (7 pending)** and **Published (1)**: *Tracing recursive return values* (seeded, `source: manual`) with its **Open help room** button; no previous AI run shown.
5. **Student A and Student B profiles:** open `/join/DEMO01` in each so they are joined (aliases "Student 25" and "Student 26"). Each student page shows the **Current topic** card (*Call stack & frames*) first, the other concepts below it, then the question box, then *Published question clusters* and the helper opt-in. In Student B, tick **I can help with Return values** and press **Volunteer as a peer helper**. Don't clear storage or reset afterwards; a room link always carries `?code=DEMO01` so each profile keeps using its own token.

## Script

**00:00–00:15 — Instructor view.** "Each student just tells us *confused / partly get it / can explain it* for the concepts of today's lecture. The graph is the live map of self-reported understanding: node colour is the class's aggregate, N is on every node, dashed border means fewer than five answers. Right now 24 simulated students — labelled as such — have answered: call stack and return values are where they're stuck. The amber **1 cluster** badge on those two nodes and the **Open clusters** card say one reviewed misconception already maps onto them."

**00:15–00:35 — A real student acts.** Student A: tap **Confused** on the *Call stack & frames* card at the top, then in the question box below the confidence cards pick *Call stack & frames*, type "after the base case returns, how do we get back to the first call?" and press **Send anonymously** (the page says it is pseudonymous to classmates — the instructor sees an alias). Point at the instructor screen: **Responses 107**, **Confused responses 43**, the node colour changes, and the button becomes **Suggest clusters (8 pending)**, with no refresh — that's a Convex reactive query, the browser only subscribes. The student's own page shows no counts and no one else's question.

**00:35–00:55 — Claude clusters.** "Eight differently worded questions are now waiting. Instead of reading them one by one we ask Claude." Press **Suggest clusters (8 pending)**. Explain while it runs (a Convex Node action scheduled in the background; the key never leaves the server): Claude gets only question text and the concept list, must answer with one structured `save_clusters` tool call, and we reject any question or concept ID it didn't receive. Open a suggested cluster: title, summary, confidence, the original questions as evidence, and the concepts it maps to.

> **Fallback if the run shows `error` or takes > 20 s:** say so plainly ("the model call failed, so we group by hand — the demo never depends on the API"). In the queue select the four stack-unwinding questions plus Student A's, press **Group selected (5) into a cluster**, title *How the stack unwinds*, summary *Students don't see how control returns to earlier frames after the base case*, concept *Call stack & frames*, then **Publish cluster**. `clusters.createManual` publishes immediately — it appears under **Published (2)** with its own **Open help room** button, **Open clusters** goes to 2 and *Call stack & frames* shows **2 clusters** — so **skip the Publish click in 00:55** and go straight to showing the cluster on Student A's page ("the instructor is the approval step here; with Claude it would be a suggestion we review first"). If even that is not an option, point at the seeded *Tracing recursive return values* cluster, which is already published.

**00:55–01:15 — Approve.** (Claude path only.) Press **Publish** on the suggested stack-unwinding cluster. It moves to **Published (2)**, **Open clusters** becomes 2, the badge on *Call stack & frames* becomes **2 clusters** and the node detail lists it — the same Claude output lights up the knowledge graph; no second AI call. On Student A's page it appears under *Published question clusters* (title, summary, question count — never the questions themselves or who asked).

**01:15–01:40 — Peer help.** Student B's cluster card shows *1 helper opted in* — a deterministic filter on who volunteered for the concept, no AI picking people. Student B presses **Open a room as helper (Return values)** on the *Tracing recursive return values* card (or the instructor presses **Open help room** on that published cluster — the room takes the cluster's first concept, *Return values*, and shows up on the card as *0 / 6 members*). The room now appears on Student A's cluster card; Student A presses **Join**. Both land on `/room/<id>?code=DEMO01`; the room header reads *for cluster "Tracing recursive return values"*, and the instructor's cluster card and *Help rooms* panel show *2 / 6*. Exchange two messages and walk the `factorial(3)` trace: `3 * factorial(2)` waits, `2 * factorial(1)` waits, `1` returns, then the products collapse upward. Capacity and membership are enforced in the mutation: a non-member's tab gets nothing from the room, a seventh person is refused.

**01:40–02:00 — Close the loop.** Instructor clicks **After help (post)** in the pre/post panel's phase toggle (the header now reads *signals: After help (post)*); Student A taps **I understand now** under *How is Return values going now?* in the room (confirmation: *Recorded under "After help (post)"*). The instructor's pre/post panel shows *Before help (pre)* vs *After help (post)* with N on both sides (post N = 1 next to the unchanged pre N = 24) — "these are self-reported signals, not verified learning gains." Wrap: **Convex** keeps every device in sync with transactional mutations and reactive queries; **Claude** turns scattered questions into a reviewable misconception mapped onto the concept graph; **Meta's** human-connection goal is served by students actually helping each other in the room.

## If something breaks

- Dashboard says *No instructor access*: the secret isn't in this browser — redo the `localStorage.setItem` line from the seed output and reload.
- Student page stuck on *Joining* / room says you are not a member: the session was reset after the student joined; remove `classpulse:student:DEMO01` from `localStorage` (or use a private window) and reload. Room links without `?code=DEMO01` cannot find the token — use the links the app generates.
- Amber *Disconnected — reconnecting…* banner at the top of a page: the browser lost the Convex WebSocket; it shows the last data received and clears by itself once reconnected.
- **Suggest clusters** button is disabled: a run is still `running`; wait for it to finish or error (the queue shows the latest run's status).
- Functions missing / "Could not find function": another branch pushed to the shared deployment — run `npx convex dev --once` from this checkout again.
- Anything else: `npx convex run seed:reset`, paste the new secret, reload all profiles. It takes ten seconds.
